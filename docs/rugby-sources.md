# データソース調査記録（ラグビー）

日本の大学ラグビーは3つの地区協会が全国を分担しており、この3地区で実質「全国対応」となる
（関東＝北海道・東北・関東・甲信越、関西＝北信越西・東海・近畿・中国・四国、九州＝沖縄含む）。

## 関東ラグビーフットボール協会 (rugby.or.jp)

- 日程・結果: `https://www.rugby.or.jp/univ/result/{ID}/`（class="gameSche"で意味づけされた
  綺麗なHTML。日付見出し+試合liの構造。パース済み・動作確認済み）
- 星取表: `https://www.rugby.or.jp/univ/sheet/{ID}/`（対戦マトリクス、公式の勝点・順位あり。
  未使用＝順位は自前集計（勝ち点3・分け1）を採用。理由: ボーナスポイント制度で公式勝点と
  ズレるため、参考値である旨を明記した上でシンプルな算出に統一）
- **重要**: URLの数値IDは年度ごとに変わる。固定IDに依存せず、毎回シーズントップページ
  （`/univ/result/nendo-{year}/`）のメニューHTMLから動的に解決する（fetch_rugby.py:
  discover_categories）
- **重要**: User-Agent必須。デフォルトのcurl/urllibだと0バイトが返る
- **重要**: リーグ戦3部以下（3部・4部・5部）は`/files/result/{ID}.pdf`へのリンクのみで
  HTML本文が存在しない。PDF配布のため対象外とした（2024-2026年度で確認）
- 対象カテゴリ: 対抗戦Aグループ・Bグループ、リーグ戦1部・2部の4つのみ
- 実装: `pipeline/fetch_rugby.py`

## 関西ラグビーフットボール協会 (rugby-kansai.or.jp)

- 日程・結果: `https://rugby-kansai.or.jp/gameuniversity`（当年度）
  `https://rugby-kansai.or.jp/gameuniversity{year}`（過去年度、例: `gameuniversity2025`）。
  rugby.or.jpと違いURLが年度ごとに固定なので動的ID解決は不要
- WordPressベースで関東より重いページだが、日程表自体はCSSグリッド
  （`class="sche_cont7"`）で、節ごとに7項目（節番号/日程/K.O./ホーム/スコアorvs/
  アウェイ/会場）が並ぶ。スコアは`<div class="score-cell">`内の
  `<a class="score-link">`または`<span class="score-text">`のテキストとして
  「NN - NN」の形で入っている（両パターンあり、score-mainのテキストから数字を拾う
  実装にして両対応にした）
- **重要**: 2023年度以前は同じCSSグリッドではなく旧`<table>`形式（列構成が別物、
  「対戦カード」列に3セル分をまとめる構成）で配信されており本パーサーは非対応。
  取得できるのは直近2シーズン（2024・2025年度）のみ
- 対象: Aリーグ・Bリーグ。**Cリーグ以下は対象外**——年度によりC1/C2が別グリッドに
  分かれていたり1つのグリッドに結合されていたりして一貫性がなく、正確な分離が
  信頼できないため見送った
- 見出しタグは`<h4 class="daiji">`のことも`<p class="daiji">`のこともある（揺れに対応済み）
- 実装: `pipeline/fetch_kansai.py`

## 九州ラグビーフットボール協会 (rugby-kyushu.jp)

- 日程・結果: `https://www.rugby-kyushu.jp/kyushuleague/{year}-{year+1}/kyushugakusei.html`
  （例: `2025-2026`）。これも年度ごとに固定URLなので動的ID解決は不要
- 表形式（`<table>`、列: NO/月/日/曜/開始時間/対戦①/(空)/対戦②/会場）。節・日付・会場は
  同じ値が続く場合`rowspan`で結合されているため、列ごとに繰り越しながら1行=1試合に
  展開するロジックが必要（fetch_kyushu.py: flatten_rows）
- スコアはPDFリンクのテキストとして「12-14」のように入っている。年度によりハイフンが
  半角"-"・全角"－"の場合があり、両対応にした
- 対象: リーグA・B・C・Dの4部すべて（九州は母数が少なく下位部を除外する必要がない）
- 当季（開幕前）ページは列構成が異なる場合があり（日付が1セルにまとまる等）、その場合は
  0試合として扱い、直近過去シーズンのチーム一覧にフォールバックする（関東・関西と同様の
  挙動）
- 実装: `pipeline/fetch_kyushu.py`

## 検討したが見送った競技（2026-08-11時点の調査）

- **アメフト（KCFA）**: 日程はHTMLテーブルで綺麗に取れるが、スコアが別ページに分離しており
  未特定。追加調査が必要
- **サッカー（JUFA関東）**: 公式サイトの結果ページが外部システムに委譲されており、
  データの所在が未特定。追加調査が必要
- **ボート・ヨット**: リーグ戦形式ではなく選手権レース形式（年数回のレガッタ）のため、
  「試合結果・順位表・対戦成績」という今回のサイト構造がそもそも当てはまらない。
  別プロダクトとして設計し直す必要がある
